# ТЗ: этап 1 — каркас, главная и навигация

## Цель

Создать в Laravel устойчивый каркас Shopra Admin, на который затем можно по одному подключать товары, заказы, витрину и остальные модули.

## Стек

- Laravel;
- Blade;
- UIkit;
- собственный компактный CSS поверх UIkit;
- JavaScript только для интерактивных элементов интерфейса.

React/Vinext из папки `prototype-source` используется только как визуальный и поведенческий референс.

## 1. Каркас админки

### Десктоп

- фиксированная левая панель шириной около 252 px;
- рабочая область справа;
- верхняя панель остаётся видимой при прокрутке;
- светлый фон рабочей области;
- белые карточки, тонкие границы, мягкие тени и скругления;
- основной акцент — тёплый оранжево-медный.

### Мобильный

- постоянная боковая панель скрывается;
- в верхней панели появляются кнопка меню, логотип и уведомления;
- меню открывается поверх страницы как выезжающая панель;
- нажатие по пункту закрывает меню и переводит в раздел;
- карточки складываются в одну колонку;
- элементы управления имеют удобную область нажатия.

## 2. Структура меню

Пункты идут одним списком, без искусственного деления на группы:

1. Главная
2. Внешний вид магазина
3. Товары
4. Заказы
5. Доставка
6. Оплата
7. Скидки и распродажи
8. Статистика
9. Домен
10. Настройки

Требования:

- активный пункт заметен по фону и акцентному цвету;
- у «Заказы» может отображаться счётчик;
- внизу панели находятся профиль владельца и компактный прогресс готовности магазина;
- выбранный пункт сохраняется после перезагрузки через текущий маршрут, а не только через JavaScript-состояние.

## 3. Верхняя панель

На десктопе:

- поиск;
- уведомления с индикатором;
- помощь;
- выбор магазина.

На мобильном:

- кнопка меню;
- логотип Shopra;
- уведомления.

Поиск и уведомления на первом этапе могут работать с демонстрационными данными, но должны корректно открываться, закрываться по Escape и не выходить за экран.

## 4. Главная страница

### Приветственный блок

- текущая дата;
- приветствие владельца;
- короткий текст о состоянии магазина;
- кнопка просмотра витрины;
- выбор даты или периода.

### Показатели

Четыре карточки:

- новые заказы;
- продажи за сегодня;
- заказы в обработке;
- товары.

Карточки должны принимать данные с сервера, даже если сначала используются демонстрационные значения.

### Последние заказы

Поля:

- номер;
- покупатель;
- время;
- сумма;
- статус.

Клик по строке на первом этапе может вести на пустой маршрут заказа или открывать нейтральную заглушку.

### График продаж

- периоды 7 и 30 дней;
- данные передаются контроллером;
- переключение периода не ломает разметку;
- если данных нет, показывается понятное пустое состояние.

Для первого этапа допустим простой SVG/Canvas-график или уже используемая в проекте библиотека. Не нужно добавлять тяжёлую зависимость только ради одного графика.

### Быстрые действия

- Добавить товар
- Создать акцию
- Добавить доставку
- Настроить оплату
- Подключить домен

До подключения модулей кнопки ведут на соответствующие маршруты-заглушки.

### Старт магазина

Обязательные шаги:

- добавить первый товар;
- настроить доставку;
- добавить способ оплаты;
- настроить внешний вид.

Необязательный шаг:

- подключить домен.

Правила:

- процент считается только по обязательным шагам;
- в компактном виде показывается ближайший незавершённый шаг;
- кнопка «Все шаги» раскрывает полный список;
- выполненные шаги визуально отмечаются;
- домен явно отмечен как необязательный.

## 5. Пустые разделы

Для всех пунктов, кроме «Главная», на этапе 1 достаточно:

- рабочего URL;
- правильного заголовка;
- активного пункта меню;
- короткого объяснения назначения раздела;
- без добавления выдуманной бизнес-логики.

Исключение: существующие последующие прототипы можно оставить только как референс, но не считать частью приёмки этапа 1.

## 6. Данные, которые отдаёт DashboardController

Рекомендуемый контракт:

- `store`
- `owner`
- `today`
- `metrics`
- `recentOrders`
- `salesSeries7`
- `salesSeries30`
- `setupTasks`
- `setupProgress`
- `notificationsCount`

Все отсутствующие данные должны иметь безопасные значения по умолчанию, чтобы главная не падала на новом магазине.

## 7. Критерии приёмки

- все пункты меню открывают отдельные маршруты;
- активный пункт определяется серверным маршрутом;
- главная совпадает с референсом по структуре и общей визуальной плотности;
- боковая панель и верхняя панель не перекрывают контент;
- мобильное меню работает с клавиатуры и касания;
- страница не имеет горизонтальной прокрутки на телефоне;
- главная корректно выглядит без заказов и без статистики;
- прогресс запуска считается правильно;
- UIkit подключён один раз и не конфликтует с текущими стилями проекта;
- нет зависимости от React;
- бизнес-логика следующих модулей не попала в этот этап.

## Порядок небольших внедрений

### 1.1 — Layout

Blade-layout, дизайн-токены, десктопная сетка, мобильная верхняя панель.

### 1.2 — Navigation

Все маршруты, активные состояния, мобильное меню, профиль и переключатель магазина.

### 1.3 — Dashboard

Показатели, последние заказы, график, быстрые действия и «Старт магазина» на демонстрационных данных.

### 1.4 — Real data and QA

Подключение контроллера, пустые состояния, адаптивность, доступность и финальная сверка.
