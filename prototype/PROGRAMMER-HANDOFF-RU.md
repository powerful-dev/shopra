## Что находится в архиве

Это интерактивный фронтенд-прототип админки Shopra. Он фиксирует текущую структуру, тексты, сценарии, адаптивность и визуальные решения. Все основные действия можно пройти в интерфейсе, но данные пока демонстрационные и хранятся в компонентах через React state.

Архив предназначен как точный визуальный и сценарный ориентир для поэтапной реализации в Laravel Blade + UIkit. Его не следует воспринимать как готовый backend.

## Технологии прототипа

- React 19 + TypeScript;
- Next/Vinext + Vite;
- UIkit;
- Lucide React для иконок;
- подготовленная конфигурация сборки для Cloudflare Sites.

Требуется Node.js `>=22.13.0`. Скрипты сборки рассчитаны на Linux/WSL и используют Bash.

```bash
npm ci
npm run dev
```

## Зафиксированные продуктовые решения

- Shopra должна ощущаться проще Etsy/Shopify: минимум терминов и настроек, максимум понятных действий.
- На главной нет выбора магазина и нет общего выбора периода. Период выбирается внутри «Статистики».
- В каталоге раздел категорий открывает только редактор дерева категорий. Добавление товара запускается отдельным действием.
- Для копирования используется формулировка «Создать на основе существующего товара». Слово «шаблон» не выводится в основной сценарий.
- Пресеты свойств и вариантов зависят от типа товара; пользователь может добавить значение, которого нет в списке.
- Если цена зависит только от цвета, таблица показывает строки цветов с ценой, а не все комбинации цвета и размера.
- Фото загружаются в общую галерею, затем привязываются к цветам/вариантам. Для первого показа выбирается основной цвет.
- В шапке витрины каталог и рубрики можно переставлять перетаскиванием. Обычные информационные страницы находятся в футере и редактируются простым текстовым редактором.
- Внешний вид построен на готовых профессиональных пресетах: 8 цветовых гамм и 8 сочетаний шрифтов, без перегруженной ручной настройки.
- Распродажа может применяться ко всему магазину, товарам/категориям, низким остаткам или выбранным цветам и размерам во всём каталоге.
- Предложения поддерживают сценарии: избранное, брошенная корзина и повторная покупка; область действия — все товары, выбранные товары или категории.
- Доставка поддерживает ручной режим без API и подключение API для расчёта/создания накладных.
- Оплата на реквизиты ФОП остаётся самым простым способом; платёжные сервисы требуют обязательной настройки.

## Что нужно заменить backend-логикой

Сейчас товары, категории, заказы, статистика и настройки заданы демонстрационными массивами. При переносе в Laravel их следует заменить моделями, сервисами, форм-реквестами, политиками доступа и API интеграций.

Минимальные сущности:

- магазины и пользователи/роли;
- товары, категории и связи товара с несколькими конечными категориями;
- свойства вариантов, значения, модификации, остатки, цены, артикулы и фото;
- заказы, позиции заказа, оплаты, отправления и накладные;
- способы доставки и оплаты;
- промокоды, распродажи, автоматические предложения и правила отбора;
- настройки внешнего вида, меню, виджеты и страницы футера;
- события статистики и агрегированные отчёты.

## Рекомендуемая последовательность внедрения

1. Перенести общий layout, меню, главную и мобильную структуру в Blade + UIkit.
2. Подключить магазин текущего пользователя, роли и реальные показатели главной.
3. Реализовать товары, дерево категорий, варианты, цены, остатки и изображения.
4. Реализовать заказы, статусы, доставку, оплату и накладные.
5. Добавить скидки, предложения и статистику.
6. Сохранять настройки витрины и рендерить по ним публичный магазин.

## Важно

В архив специально не включены `.git`, `node_modules`, `.sites-runtime` и готовая папка сборки `dist`. Это уменьшает размер и исключает локальные служебные данные. Зависимости устанавливаются из `package-lock.json`.
